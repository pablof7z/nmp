# Current surface and gaps

Verified-Revision: `be56577ba4c728ed545b45ac0b20565d70ea2fa3`

This pins the declared product/source authorities, not the skill package commit. Recheck the [source map](source-map.md) when any declared authority changes; the validator accepts newer skill-only commits when those sources have not drifted.

## Supported consumer tiers

| Tier | Supported entrypoint | Reactive result | Lifecycle |
| --- | --- | --- | --- |
| Rust | `nmp::Engine` | blocking `Subscription` / `DiagnosticsSubscription`; receipt channels | subscriptions withdraw on drop; call `shutdown` or drop engine |
| Swift | `NMPEngine` from `NMP` | `NMPQuery` and `NMPDiagnostics` `AsyncSequence`; `Receipt.status` | query/diagnostics cancellation and iterator-owned teardown; engine `shutdown` with `deinit` backstop |
| Kotlin/JVM | `NMPEngine` from `com.nmp.sdk` | cold `Flow<RowBatch>`, `Flow<DiagnosticsSnapshot>`, `Receipt.status` | cancel collectors; use `NMPEngine.use {}` or call `close`/`shutdown` |

Mechanism crates and generated `NMPFFI`/`uniffi.nmp_ffi` bindings are implementation seams, not alternate application APIs.

## Important gaps

- Public `Row` values expose the signed event and the relay source set. They do not expose typed `Pending(intentId)`/`Signed(signature)` state, intent ids, or receipt ids. Pending-row mechanics exist internally and in the north-star contract; do not make an app depend on public metadata that is absent.
- The write vocabulary is the custody model, not a flat status enum. `WriteFact` is exactly `Signing(SigningState)`, `Relay { relay, state }`, `Destinations { relays, complete, awaiting_author_routes }`, and `Outcome(WriteOutcome)`. `SigningState` is `AwaitingSigner { pubkey }`, `InFlight { pubkey }`, `Signed { event_id }`, `Refused { reason }`. `RelayState` is `Waiting(RelayWaiting)`, `Sent { attempt, written_at }`, `Published`, `Rejected { reason }`, `AuthFailed { pubkey, source, reason }`, `GaveUp`. `RelayWaiting` is `NotConnected`, `NeedsAuth`, `BackingOff { attempt, eligible_at, cause, detail }`, `PersistenceStalled { detail }`. `WriteOutcome` — the only whole-write terminal — is `Settled`, `NoDestination`, `NotSent(Cancelled|Superseded)`, `Refused(RefuseReason)`.
- `Destinations` separates *where this write is intended to go* from *whether that picture is settled*. `complete` flips on settled resolution, never on successful delivery, so `complete: true` with every relay unpublished is an ordinary state. `awaiting_author_routes` names the public keys whose routes resolution is still waiting on, as keys rather than as a sentence.
- `RelayState::Sent { attempt, written_at }` means transport proved socket write and flush for that persisted attempt. It is not an ack and it is not terminal. `RelayWaiting::BackingOff` carries the engine-owned durable scheduler's persisted attempt ordinal, deadline, and a typed `RetryCause`; it is evidence, not an app retry door. There is no app-controlled retry method on any tier.
- `Engine::cancel(receipt_id)` cancels a write that has not yet been signed, committing `WriteOutcome::NotSent(NotSentReason::Cancelled)`. It refuses with typed `CancelWriteError::AlreadySigned`/`AlreadyCompensated`/`AlreadySuperseded`/`AlreadyRefused` once the write has moved past that point. Cancelling a write is distinct from detaching a live fact stream.
- `Engine::publish_queue()` enumerates every retained write with its full current state as `PublishQueueEntry`, and `remove_publish_queue_entry` is its companion. A write parked on a missing signer, and a permanently-failed entry, end only by the app's own decision: cancel the parked one, then remove whichever terminal entry is left. Retained receipts and correlation tokens still grow without bound (#46); the queue door makes that growth visible and does not fix it.
- A refusal before acceptance takes nothing into custody: no receipt, no stream, and no queue entry exist for it. A stale replaceable base is *not* pre-acceptance — it takes custody and becomes a readable `Refused(RefuseReason::ReplaceableBaseChanged { expected, actual })` queue entry, which keeps both ids so an app can refetch `actual`, reapply, and resubmit without troubling the user.
- Reattachment returns `Attached`/`NotFound`/`RetainedButUnreadable` and traverses the durable `WriteFact` history in finite pages before streaming onward. Stream lag is the typed `FactStreamLagged`, not silent loss. `WriteIntent.correlation` plus `reattach_by_correlation` closes the crash window between acceptance and the app persisting the receipt id, because the token is caller-minted and journaled inside the same acceptance transaction.
- `LiveQuery` is the observation noun on every tier: a `Vec<Demand>` of at most `MAX_BRANCHES` (64) branches plus an optional `aggregate_result_limit`. Branch order and duplicates are canonicalized, so permutations of the same branch set are one value. `RowBatch.evidence` is one entry per canonical branch, in branch order. `LiveQueryError` is `EmptyUnion`, `AggregateResultLimitZero`, `NestedAggregateResultLimit`, and `TooManyQueryBranches { requested, maximum }`.
- `Demand` has five fields: `selection`, `source`, `access`, `cache`, and `freshness`. `Freshness` is `Live` (default), `MaxAge { seconds }`, or `CacheOnly`, and is deliberately excluded from atom, wire, and coverage identity.
- `Row.sources` is the set of relays that *hold* the event, not whatever delivered it first.
- Rust diagnostics carry fields the native wrappers do not project: `discovered_private_relays_rejected`, `sessions_rejected_over_cap`, `sessions_refused_by_subscription_budget`, `store_degraded`, and the relay-level `subscription_budget`, `subscriptions_refused`, `subid_length_limit`, `subid_length_rejects_our_ids`. Swift/Kotlin expose relay summaries (including `access`, which together with the URL is the relay row's identity), `authSessions`, uncovered author count, dropped merge rules, `transportDegraded`, `stalledWrites`, and `stalledWriteTotals`. `store_degraded` is reachable only from direct Rust — raw UniFFI does not project it either.
- `AuthPhase` and the AUTH-related `SourceStatus` variants are populated for `AccessContext::Nip42` sessions from exact session/generation bookkeeping. Only `AccessContext::Public` sessions can never reach them.
- Rust `EngineConfig` carries `indexer_relays` and `max_publish_attempts` that the hand-written wrappers omit. Swift/Kotlin `NMPConfig` expose `storePath`, `appRelays`, `fallbackRelays`, `allowedLocalRelayHosts`, `torReachable`, `maxRelays` (default 10), and `maxAuthCapabilities` (default 64). No tier exposes any worker/task/thread capacity: #704 removed all application-configurable task admission.
- Swift and Kotlin each ship a genuine secure account store — `NMPKeychainAccountStore` over `SecItem`, and a `java.security.KeyStore`-backed store — alongside the explicitly insecure plaintext file stores. All satisfy the same `NMPLocalAccountCheckpoint` contract, so the engine restores from whichever conformer is injected. Prefer a platform-vault conformer. The Kotlin secure store is desktop-JVM `KeyStore`, explicitly not AndroidKeyStore. Secret zeroization remains incomplete.
- Kotlin is a desktop JVM falsifier, not an Android AAR. Android OS handoff code belongs to the host; NIP-55 execution is not shipped. A narrow optional desktop-JVM Compose subproject (`:ui`, `com.nmp.ui`) ships relay identity/list primitives only; broad Compose parity and a Compose gallery are unbuilt.
- NIP-11 snapshots are process-local and engine-owned; cross-process persistence is not shipped. The cache retains at most 256 last-good snapshots. One engine admits at most 8 live distinct-relay HTTP/DNS/body flights; `Refresh` coalesces same-relay callers onto one generation-guarded completion and excess callers suspend cancellably in their own futures without a public refusal. Reducer evidence is retained only for relays in the current read plan and diagnostic freshness expires from the engine clock at the cited document deadline. The production request uses explicit Hickory DNS plus rustls HTTP under one three-second total deadline, rejects URL credentials, follows no redirect, and performs no automatic retry. Swift tests run on the macOS host and the generated simulator slices compile; an iOS Simulator runtime harness remains open in issue #465. Kotlin tests target desktop JVM, and there is no Android/AAR qualification.
- NIP-02 follow/unfollow preserves an existing contact list and refuses a missing base. First contact-list creation is a separate, unshipped policy. `nmp-nip02` depends on `nmp` and therefore cannot be re-exported through the facade; `nmp-ffi` binds it directly, and both wrappers surface it on `NMPEngine`.
- There is no NIP-23 owner: no crate, no `Article` type, no decode. `NMPUI` does not decode NIP-23 either. A design that composes an article must add the owner from scratch.
- Content support is parser-only on every tier. The typed profile/article resource layer and the bounded reference-session machinery were deleted (#561): there is no `NMPContentClient`, no `NostrContentSession`, no `claim(referenceID:)`, and no session permit budget. Parse a row's content, then open ordinary queries per resolved locator.
- Observations and logical adapter work run as async tasks on one shared engine-owned runtime. No OS thread is consumed per observation/session wait, and there is no worker/task/thread capacity refusal; private NIP-11 bounds backpressure producers. `EngineStartFailed { component, reason }` is construction-only. `ObservationUnavailable { reason }` means only that store degradation prevented an ordinary or windowed observation's initial canonical projection from opening; relay connection/worker failure is ordinary acquisition evidence. These two are not the whole of `EngineError`: store-open, relay-URL, window-validation, live-query-construction, `AuthCapabilityRegistryFull { limit }`, and `EngineClosed` are separate typed doors, and the capability registry bound is an application-configured ceiling.

## Raw UniFFI parity seam

Generated `NMPFFI` / `uniffi.nmp_ffi` bindings are not the supported ergonomic app tier, but they are the projection seam the native wrappers must preserve. At this revision `NmpEngineConfig` includes `allowed_local_relay_hosts` and `max_relays`; `NmpEngine` exposes filter/demand/live-query observation, publication, receipt reattachment by id and by correlation token, publish-queue enumeration and entry removal, write cancellation, governed sign-only through `NmpSignEventHandle` (`signed()` plus `cancel()`), diagnostics, lifecycle, one-shot relay information, and following. The read path is pull-based single-consumer handles, not observer callbacks: `observe` returns an `NmpRowStream`, whose `begin_next`/`receive`/`commit`/`abort` cycle is why `FfiError::ConcurrentNext` exists. NIP-29 is entirely off-engine on `FfiRelayScope`/`FfiGroup`/`FfiGroups`. NIP-22 composition is the engine-free top-level `comment_intent(target, content, correlation) -> Result<FfiWriteIntent, FfiError>`. `FfiError` distinctly projects `EngineStartFailed { component, reason }` (engine construction only) and `ObservationUnavailable { reason }` (ordinary or windowed initial canonical-projection setup only); every other NIP-11 acquisition failure crosses as the typed `RelayInformationUnavailable { kind: FfiRelayInformationErrorKind }` boundary (#494) rather than an empty document or a message string. `FfiRelayInformation.lastError` is likewise a typed enum, not a string. There is no worker/task census, idle-barrier method, or worker capacity refusal: private physical bounds backpressure without becoming app scheduling vocabulary. Native app code should use `NMP` or `com.nmp.sdk` and must not reach around a wrapper gap by importing generated types.
