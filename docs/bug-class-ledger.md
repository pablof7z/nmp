# Bug-class acceptance ledger

This ledger replaces governance-by-lint. A bug class is closed only when a
type/API mechanism makes the bad path unreachable and a falsifier demonstrates
that fact. `TARGET` records an agreed invariant whose mechanism is not built;
`PARTIAL` means current proof covers only part of the promoted contract.

| # | Bug class | Structural exclusion | Current proof status |
|---|---|---|---|
| 1 | **Stale replaceable event retained** | One canonical mutating store door performs exact-id dedup, then replaceable arbitration; no public index setter exists. | **BUILT / M3 verified.** Both stores exercise supersession through the door; retraction of the displaced row is tracked separately. |
| 2 | **Lost or leaked subscription** | Wire demand derives only from refcounted live-query descriptors; there is no public open-REQ verb. NIP-77 acquisition activates a role-separated `REQ {limit:0}` through its exact EOSE before taking the reconciliation snapshot, keeps that live owner open through NEG/backfill, and overlap-closes only after the replacement is proven. | **BUILT / M2 verified; gap-free NIP-77 handoff verified by #563.** Surgical open/close and last-observer withdrawal have headless proofs; boundary, overdelivery, failure, timeout, reconnect, and genuine-relay falsifiers cover the handoff. |
| 3 | **Wrong-relay routing through app relay injection** | Automatic relay selection is compiler output from a read-only neutral fact surface. One atomic author fact owns both outbound and inbound sets; its production writer is private, borrowed, and non-cloneable. Protocol components declare ordinary needs and can replace only the complete fact, never install a router kind/lane or half-mutate one direction. App-constructible exact routing remains deliberately available as `WriteRouting::Explicit` and `SourceAuthority::Pinned`; those values scope only their own operation, bypass automatic facts and operator additions, and cannot mutate later routing. | **BUILT (#870).** `RelayDirectory`/`LiveDirectory`, discovery-kind/indexer routing, protocol lanes, pinned directory lookup, and half-mutators are deleted. `RoutingFacts` is read-only; `AuthorRouteState` is exactly `Unknown | Present { outbound, inbound } | Absent`, keyed internally by decoded `PublicKey`. The engine-free `nmp-nip65` coordinator supplies the first optional protocol assembly; feature-disabled core has no NIP-65 dependency. Router, exact-route, pure coordinator, atomic replacement/restart, and dependency-tree falsifiers cover the boundary. |
| 4 | **Uncapped fan-out** | Every plan carries an explicit cap and reports uncovered demand; no relay outside the compiled plan is contacted. | **BUILT for the current engine (#20, #442, #446, #467, #598, #680, #704).** The router applies one deterministic relay ceiling; refused atoms retain `LocalLimit` evidence. Live and charged-retiring relay workers and verifier workers have explicit finite owners bounded by `max_relays`. Access-scoped Public and `Nip42(author)` sessions never share a socket, while reducer-typed read/write admission gives a nonterminal write bounded same-relay time-sharing priority when the physical cap is one (#598): only write ownership may release the same relay's Public worker; protected reads cannot claim that authority; no other relay is evicted; terminal reconciliation restores still-owned Public demand on a fresh generation. Rust falsifiers and a public macOS-host Swift XCTest prove operator-app routing, one publish/ACK, and read restoration at `maxRelays = 1`. **Observation delivery no longer owns an OS thread (#680):** row, window, diagnostics, follow, receipt, and follow-action streams are waker-driven async pull handles over engine-owned bounded mailboxes, so NMP OS-thread count is independent of the number of live observations (a 1,000-handle scaling falsifier proves 0 thread growth) and there is no app-visible native-task capacity — `max_native_tasks`/`maxNativeTasks`/`ExecutorSaturated` are removed from every SDK. Snapshot mailboxes conflate exactly; FIFO fact streams retain a fixed 32-item prefix and surface typed lag, with durable receipts replayed through finite pages using identity-stable continuation state bounded by relay fan-out and consumer close/drop detaching its exact runtime delivery registration. This bounds live delivery, not total persisted attempt retention, which remains tracked under #46. **Internal capacity refusal is also gone (#704):** one engine-owned async runtime hosts ready-or-pending adapter work; waker-driven completion doors park no worker thread, and no operation can be refused because an internal scheduler is occupied. Physical resources remain bounded by private backpressure: NIP-11 admits at most 8 distinct HTTP/DNS/body flights and coalesces same-relay callers onto one shared completion,; foreign completions whose contract permits blocking run on fresh per-operation threads rather than an admitted internal pool. `docs/design/durable-write-signing-and-retry.md`, `docs/design/async-observation-handles.md`, and `docs/design/internal-executor-elimination.md` record the current architecture; `native-task-executor.md` is retained as the superseded record. |

| 6 | **Private-event republish** | Private/narrow route values have no widen operation; unresolved private routing fails closed. | **BUILT for current narrow route types; future protocol modules must preserve it.** |
| 7 | **Cache evidence presented as global truth** | Query snapshots expose rows plus per-current-plan source facts and explicit shortfalls, computed over every root and interior atom. Coverage authority is private request state: an EVENT transaction failure monotonically poisons only the exact request/session/wire FIFO owners that could have emitted it; ordinary EOSE and NIP-77 completion consume that state through one request-atomic coverage door. | **BUILT (#12/#49/#714/#816).** Rust/FFI/Swift/Kotlin carry `AcquisitionEvidence`; full `SourceAuthority + AccessContext` identity partitions coverage and evidence; offline cached rows coexist with scoped disconnected/watermark facts; no public aggregate claims completeness. #816 falsifies ordinary and missing-ID EVENT failure, overwritten-FIFO and access-session isolation, post-commit projection failure, concurrent healthy completion, atomic multi-claim MemoryStore/Redb behavior, semantic-oracle reopen parity, and the four real Redb event/coverage commit crash seams. | 8 | **Assuming NIP-77 support** | Negentropy requires a capability token minted only after behavioral probe; NIP-11 advertisement is tracked separately and can never mint the token. Unprobed relays use REQ. | **BUILT / M3 verified; NIP-11 evidence split verified by #185.** |
| 9 | **Accepted/enqueued treated as converged** | Acceptance is not a fact on the stream at all: `publish()` returning `Ok` IS acceptance, and it is constructible only after atomic persistence of intent, receipt, frozen body, and canonical pending row. Delivery is per-relay receipt evidence, and the stream ends with exactly one whole-write `WriteOutcome`, so "finished" and "dropped subscription" are distinguishable. | **BUILT for Rust (#1237).** Crash/reopen, stable reattachment, per-relay attempt facts, and — new — a real per-relay attempt ceiling are proved. Facts about the whole write and facts about one relay live on different arms of `WriteFact`, so "is this over?" is answerable rather than re-derived by each consumer from doc comments (the defect #1237 recorded: four hand-written taxonomies in one repo, disagreeing about the same variant). `RelayState::is_terminal` and `PublishQueueEntry::is_terminal` answer it once. Live fact delivery is a fixed-capacity FIFO with typed lag, finite-page durable replay uses an identity-stable per-lane continuation so mutation between pages neither skips nor duplicates evidence, and consumer close/drop deterministically removes its identity-bound live delivery registration even if the receipt never emits again. |
| 10 | **Signer drift after acceptance** | Publish defaults to the signer for `$currentPubkey`, permits an explicit identity override, then freezes the selected expected author at `Accepted`. | **PARTIAL.** Default-author freezing, exact-pubkey restart resume, and real delayed reattachment of an app-supplied signing capability are built; explicit per-write override and standard platform vault providers remain. |
| 11 | **App owning interest expansion** | `Derived`/`SetOp` resolve inside the engine; helpers return the same closed printable graph; no expanded-set callback exists. | **BUILT for the raw grammar.** Module-provided reusable fragments remain TARGET. |
| 12 | **Presentation or plaintext policy in core** | Engine/module values contain protocol-semantic raw data only. | 13 | **Late-arriving event skipped by presentation pagination** | Windowing is a policy on the one read noun: `observe(query, window)` with an engine-owned expandable window maintains the complete bounded canonical partition ordered by the exact exclusive `(created_at DESC, event_id ASC)` cursor. Growth is the declarative, monotonic `request_rows(at_least:)`; the host never constructs, holds, or replays a protocol cursor or continuation token. Acquisition cursors remain separate engine state. | **BUILT across Rust, UniFFI, Swift, and Kotlin (#474, resurfaced per #485).** Same-timestamp rows advance with exact exclusive ordering across multiple pages; newer/late arrivals, retractions, replacement, expiry, compensation, and provenance growth rebalance one atomic row set. Delivery mode derives from boundedness (unbounded ⇒ exact rebased deltas whose intermediate reducer emits may conflate, windowed ⇒ conflated authoritative snapshots), `AtBound` is a mechanical frame fact rather than an error, store failure preserves the last rows, and cancellation withdraws the session exactly once. Durable cursor resume and a global end verdict are deliberately not claimed. |

| 15 | **Pending write bypasses normal query semantics** | `Pending(intentId) | Signed(signature)` is state on the canonical store row; acceptance, promotion, cancellation, replacement, delete, and expiry all use the one store mutation path. | **BUILT.** Pending visibility and restart/cancellation use the ordinary store/resolver graph; no optimistic overlay exists. |
| 16 | **Durable obligation lost or duplicated by retry layers** | Durable delivery is the sole persisted `(intent, relay)` attempt owner; transport owns sockets only; signer adapter owns one RPC; one deadline scheduler owns time. Already-expired work is refused before custody. Rust/FFI/Swift/Kotlin receipts project supersession, waiting, eligibility, and persisted written-handoff truth without collapsing queue acceptance into `Sent`. **The attempt ceiling (#1031) closes the "retried forever" half:** it counts observations rather than wall-clock, so a relay that keeps refusing is given up on per-lane while a lane that merely sat offline spends nothing — and an unresolved route or an unattached signer has no cap at all, because nothing accumulates there to justify one. |
| 17 | **Silent truncation under limits** | Every graph/wire/relay/result limit either preserves exact semantics, rejects explicitly, or emits shortfall evidence. | 18 | **Demand policy or evidence conflated across nested source/access/cache/freshness boundaries** | Descriptor identity is `selection + source authority + access context`; every root and `Derived.inner` Demand owns one cache projection and one opening-time freshness decision over its exact atom scope. | 20 | **Destructive replaceable edit composed or accepted from a stale base** | A protocol operation first establishes a source-scoped canonical base, preserves fields it does not own, and carries that exact event id into the store's atomic acceptance transaction. | 21 | **Live persistent store deleted or double-opened while owned** | `RedbStore::open` first acquires one nonblocking cross-process exclusive lock on a durable sidecar keyed by the resolved canonical pathname, then NMP's required backend acquires a second long-lived lock on the actual target inode before redb initialization. Destructive reset acquires the same pathname ownership, joins the target-inode lock, validates that the file has exactly one link, and holds both through removal, so no check-then-delete or unlink-one-name gap exists. Every status must remain honest. A design document, issue, or passing adjacent
test is not proof. Promoting `TARGET`/`PARTIAL` to `BUILT` requires a falsifier
against the supported public facade and, where applicable, restart and platform
projection tests.

PR review applies this same rule prospectively, before a new bug class ever
needs a row here: see `docs/design/architecture-review-gates.md` for the six
review gates (Noun, Reachability, Bool-Lifecycle, Destructive-API, Cross-SDK
Parity, Falsifier-honesty) this ledger's rule expands into at review time.
